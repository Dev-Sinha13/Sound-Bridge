# Sound-Bridge development

- The user requested consistent, frequent pushes to `https://github.com/Dev-Sinha13/Sound-Bridge`.
- Commit and push each coherent, tested implementation milestone to the current working branch. The initial project uses `main`; preserve the user's later branch choices. Use conventional commit messages such as `feat:`, `fix:`, `test:`, `ci:`, and `docs:`.
- Run the tests relevant to a change and `python -m ruff check src tests scripts` before pushing. Do not force-push or rewrite published history.
- Keep recordings, embeddings, model weights, generated experiment artifacts, caches, environments, and credentials out of Git. Small synthetic fixtures should be generated by code.
- Label synthetic datasets independently of the encoder. Runtime checks are not evidence of environmental-audio retrieval quality.
- Preserve the distinction between the CLAP baseline, frozen Audio-JEPA plus MPNet experiments, and the unimplemented good-view text/audio JEPA research direction.
